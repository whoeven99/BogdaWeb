# 项目协作说明

本文件用于约束官网改造期间的项目协作方式、上下文规则和决策落点。

## 1. 项目定位

项目名称：BogdaWeb 官网改造  
核心目标：将官网升级为统一品牌前台，而不是继续维护多个割裂站点。

## 2. 当前代码边界

- `ciwi-web/`
  - 官网主前台
  - 未来承接品牌、产品、方案、博客前台、演示能力
- `monitor/`
  - 与本轮官网改造无直接关系，默认不动

## 3. 协作原则

- 所有官网相关讨论，优先回到 `doc/` 目录沉淀。
- 先确定信息架构和页面边界，再进入大规模实现。
- 优先复用现有前端工程，不新增无必要的独立站点。
- 演示能力只做轻交互，不直接复制产品后台。
- 所有新页面都应服务于品牌、转化或 SEO，避免纯堆砌页面数量。

## 4. 技术原则

- 前台统一以 Next.js 为中心。
- 前后端统一使用 Next.js。
- 如需要数据库，统一使用 Turso。
- 优先使用静态生成、缓存和可复用组件。
- 内容源允许分离，但前台品牌体验必须统一。
- 不在一期引入过重的基础设施，先跑通主路径。
- 新版官网不以 Ant Design 作为主要组件渲染层，优先自定义组件与轻量交互原语。

## 5. 内容原则

- 文案应体现 Shopify 电商理解，而不是泛 AI 表述。
- 页面结构应优先回答商家问题：能解决什么、效果是什么、为什么可信。
- 产品页与博客页之间应形成自然内链。
- 对比页、案例页、博客页都应服务 SEO 承接。

## 6. 决策记录规则

以下信息应及时补充到文档中：

- 范围变化：更新 `plan.md`
- 执行项变化：更新 `tasks.md`
- 协作约束变化：更新 `agent.md`
- 设计与内容表达变化：更新 `design.md`

## 7. 当前已确认决策

- 官网需要统一品牌语言。
- 官网需要具备可扩展的演示能力。
- 博客能力必须保留。
- 技术上应优先支持长期扩展和加载性能。
- `ciwi-web` 应逐步成为唯一前台品牌层。
- 前后端统一使用 Next.js。
- 如需要数据库，统一使用 Turso。

## 8. 风险提醒

- 当前官网导航与真实路由不完全对应，后续改造要先解决结构一致性。
- 仓库中仍有部分历史静态产物待清理，改造时需要明确哪些保留、哪些迁移、哪些删除。
