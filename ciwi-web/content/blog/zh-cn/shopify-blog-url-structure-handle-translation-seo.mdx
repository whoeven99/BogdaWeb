很多 Shopify 团队会先把 blog 正文翻译完，再回头处理 URL。这个顺序通常会带来返工。文章虽然已经本地化，但如果 handle 仍停留在源语言，搜索意图匹配、点击信任感和站内一致性都会一起变弱。

<Callout title="先看结论">
  <p>先决定市场级 URL 结构，再决定哪些文章 handle 要翻译、哪些应该保持稳定，以及哪些旧 URL 需要在发布前完成重定向。</p>
</Callout>

## 先定结构，不要先改单篇文章

在动任何 blog handle 之前，先决定每个市场会如何暴露。实际工作里，通常就是确认本地化内容会落在子目录、独立域名，还是 Shopify Markets 当前生成的 URL 结构里。

如果这一层不稳定，文章级别的 SEO 工作也会变得脆弱。一个本地化 slug 只有在完整路由结构同样明确告诉搜索引擎“这是谁的市场页面”时，才真正有价值。

## 到底哪些内容应该翻译

围绕 blog SEO，通常有三层：

1. 用户看到的文章标题。
2. 搜索引擎先读到的 meta title 和 description。
3. 进入永久路径的 URL handle。

前两层通常都应该本地化。第三层则不一定。只有当目标市场确实用本地语言搜索，并且新 slug 能明显提升清晰度时，才值得翻译。

## 什么情况下翻译 handle 更值得

当下面三件事同时成立时，翻译 blog 文章 handle 往往更划算：

- 目标受众确实用本地语言搜索
- 当前源语言 slug 在这个市场还没有明显积累
- 翻译后的 slug 可以保持简短、可读，而且和关键词相关

例如：

- 更好：`/pt-br/blogs/news/guia-de-tamanho-infantil`
- 较弱：`/pt-br/blogs/news/complete-definitive-childrens-sizing-guide-for-seasonal-shopping`

重点不是逐字翻译。重点是让 URL 与当地搜索表达自然对齐。

## 什么情况下保留源语言 handle 更稳

有些时候，更好的做法反而是保留原 handle，只把其他 SEO 层做好。

这通常发生在：

- 文章已经有外链或已有排名
- 主题更偏品牌表达，而不是搜索流量
- 翻译后的短语会变得很长或很别扭
- 团队很难长期保持严格的重定向治理

在这种场景下，本地化标题、描述、正文、内链和 hreflang，依然能完成大部分 SEO 价值。

## Shopify handles 的判断原则

要把 Shopify handle 当成编辑资产，而不是普通翻译结果。

这意味着：

- 保持小写
- 尽量短
- 连字符规则一致
- 删掉无意义修饰词
- 优先用当地用户真实会搜的表达
- 不要翻译品牌名、SKU 逻辑或内部标识

如果一个 slug 长到你不愿意把它放进导航菜单，那它大概率也不适合出现在 URL 里。

## 团队最容易漏掉的 blog SEO 细节

在 Shopify blog 上，用户看到的正文只是页面的一部分。很多团队会漏掉配套的 SEO 层：

- 文章标题
- meta title
- meta description
- article handle
- 指向相关文章的内部链接
- canonical 映射
- hreflang 映射
- sitemap 可发现性

只要其中一层停留在源市场，页面就会呈现出“正文翻了，但整体还没翻完”的状态。

## 一个更稳的上线顺序

通常更干净的流程是：

1. 导出准备本地化的 blog 文章。
2. 标记哪些文章以搜索流量为主，哪些以品牌内容为主。
3. 优先为搜索型文章翻译标题、meta 字段和 handle。
4. 提前整理旧 URL 到新本地化 URL 的重定向映射。
5. 在同一轮发布里同步上线 hreflang 和 canonical。
6. 发布后更新 sitemap 和站内内链。

这个顺序能显著降低“新 slug 已上线，但搜索引擎还看不懂、用户也找不到”的问题。

## 最常见的几个错误

### 逐字翻译 handle

逐字翻译通常太长，也不符合真实搜索表达。slug 应该围绕市场关键词，而不是围绕句子直译。

### 重定向做得太晚

如果一个已被索引的 handle 被修改，但旧 URL 没有映射，新旧权重就会出现可避免的流失。

### 规范混用

有些团队会翻一部分 slug，留一部分英文，再混入下划线或不同大小写。搜索引擎虽然还能抓，但治理会越来越乱。

### 忘了 blog 列表层

问题不只在 article slug。本地化之后，blog 列表页、归档页和相关文章链接也必须一起保持一致。

## 更好的治理方式

你不需要翻译每一个 blog handle。你真正需要的是一套可重复执行的规则。

一套实用规则通常是：

- 对搜索导向文章，在有明确本地语言搜索需求的市场翻译 handle
- 对已有较强权重的旧 URL，除非收益非常明确，否则优先保持稳定
- 每个市场只使用一套 slug 规范
- 任何已索引 URL 的修改都必须配套重定向

做到这几条，通常就足以把多语言 SEO 管得很干净，而不用制造不必要的迁移成本。
