三、找到的三处结构问题

3.1 noindex 页却参与 hreflang 组，还带自指 canonical

GET https://ciwi.ai/zh-cn/affiliate/
HTTP/2 200
<meta name="robots" content="noindex, follow">
<link rel="canonical" href="https://ciwi.ai/zh-cn/affiliate/">
<link rel="alternate" hrefLang="en"      href="https://ciwi.ai/affiliate/">
<link rel="alternate" hrefLang="zh-CN"   href="https://ciwi.ai/zh-cn/affiliate/">
<link rel="alternate" hrefLang="x-default" href="https://ciwi.ai/affiliate/">

英文侧 /affiliate/ 同样是 noindex, follow，并反向指向中文版。于是这一对 URL 既是"我不许你收录"，又是"我是这组语言版本的正本"，还互相声明对方存在。Google 处理这种矛盾时只能二选一：按 noindex 不收录，然后归到"重复"里——因为别的标签它也用不上。

同一模式还出现在 /privacy-policy/（英文可收录、中文 noindex），英文页照样把 hreflang 指向一个 noindex 的中文页。hreflang 指向 noindex 页在 GSC 里是明确会报的 hreflang 错误。

修法：buildPageMetadata 里增加 isZhNoIndexPath()（/affiliate、/privacy-policy、/terms-and-conditions 三个前缀），命中时把 zh-cn 从 hreflang 列表里剔掉；noIndex 为真的页面整体不再输出 alternates。

已修复 src/lib/seo/metadata.ts + scripts/seo-description.test.mjs（新增 3 条回归测试）。本地预览实测：/affiliate/ 与 /zh-cn/affiliate/ 均为 canonical 0 / hreflang 0 / noindex；/privacy-policy/ 只剩 en + x-default 两条；/zh-cn/privacy-policy/ 无 alternates。

3.2 ?__ciwi_locale= 能造出任意页面的 200 重复副本

GET https://ciwi.ai/compare/transtore-alternative/?__ciwi_locale=zh-cn
HTTP/2 200                              ← 200，不是跳转
正文 CJK 占比 56.9%（即中文内容）
<link rel="canonical" href="https://ciwi.ai/zh-cn/compare/transtore-alternative/">

GET https://ciwi.ai/zh-cn/compare/transtore-alternative/?__ciwi_locale=en
HTTP/2 404                              ← 反方向直接 404

middleware 把路径语言和 __ciwi_locale 参数分开取值，参数优先。结果是任何一个英文 URL 都能靠加参数变成中文页面的 200 副本，反过来却 404。这类 URL 不在 sitemap 里、页面里也没有指向它们的链接（只在 RSC 载荷中出现），所以目前不是主要流量入口，但它是无上限的可抓取重复面：一旦有人外链、或被别的爬虫拼接出来，就会给每个页面再添一个"无 canonical 的可选副本"，正好喂养这个 bucket。

同一接口还把 ?__ciwi_locale=en 打到中文路径上时返回 404 空壳页（390 字符），这也是可避免的错误页。

修法：middleware 里把"参数语言 ≠ 路径语言"统一收敛成 308：跳到正确语言路径；参数与路径一致时 308 去掉参数。内部 rewrite 不受影响（rewrite 不会二次进 middleware）。

已修复 src/middleware.ts。本地预览实测：

/compare/transtore-alternative/?__ciwi_locale=zh-cn  → 308 → /zh-cn/compare/transtore-alternative/
/zh-cn/compare/transtore-alternative/?__ciwi_locale=en → 308 → /compare/transtore-alternative/
/?__ciwi_locale=zh-cn                                 → 308 → /zh-cn/
/compare/…/?__ciwi_locale=en&utm_source=x               → 308 → /compare/…/?utm_source=x

其他参数（UTM 等）保留，只摘掉 __ciwi_locale。尾斜杠、双斜杠折叠、/help-center/ShopifyApp 大小写修复这些既有跳转做了回归抽查，全部仍是一次 308。

四、为什么 Google 会这样归类

"Duplicate without user-selected canonical" 的含义是：Google 认为这个 URL 和另一个 URL 是同一个东西，并且在它看来这一组没有可用的正本声明。它不等于"页面上没有 canonical 标签"——页面上的标签 Google 读到了，只是没采信。三类情况会导致不采信：

  • 同一个 URL 能在不同地址返回同一份内容（本例 3.2 的 ?__ciwi_locale=）；
  • canonical / hreflang / noindex 三个信号互相打架（本例 3.1）；
  • 页面正文里包含明显的占位、错语种、或非读者内容，Google 判定"这一份不是给人读的版本"，转而去用同组的另一份（本例 3.3）。

而这 11 条里有 6 条的内容在 Google 上次抓取之后被改过（5 条是 11-16 改的），所以即便前三条都修好，也还得等重新抓取才会改判。现在这批结论至少是"过期结论"。

6.1 线上跳转实测：跳数与锚点

规则从 next.config.ts 搬进中间件之后，唯一能让「一次跳转」失效的是 Next 自己的尾斜杠归一化——它在中间件之前执行，中间件看不到原始地址。所以这里不看中间件的返回值，而是对 standalone 构建发真实 HTTP 请求、手工逐跳跟随。

样本：legacyRouteMap + legacyExtraRootRedirects + compareSlugRedirectMap + legacyHelpCenterSlugRedirects 全部 90 条旧地址，每条取「带斜杠 / 无斜杠 × 英文 / 中文」四种写法，共 360 个 URL，全部带 ?utm_source=audit&utm_medium=smoke。

/product-title-generation2200无保留
/zh-cn/product-title-generation/1200无保留
/zh-cn/product-title-generation2200无保留

七、核对方法

  • 11 个 URL 全部实时 curl（含 Googlebot UA 与普通 UA 各一次，排除 cloaking）：状态码、rel=canonical 数量与取值、hreflang 三条、<html lang>、meta robots、响应头 cache-control / vary。
  • 网络抓取 330 个站内页面，抽取 <main> 可见文本，做 6-gram shingle + Jaccard 两两比对；中英配对单独比一次。
  • 正文长度按段落分组取中位数与百分位，判断是否属于"薄页"。
  • 内容最后改动日取自 git log -1 对相应内容文件的最后一次提交，与 GSC 的 Last crawled 对表。
  • sitemap 用线上 /sitemap.xml（1,716 条）而不是本地构建产物。
