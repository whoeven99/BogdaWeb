## 修复实施（同日）

### 诊断修正（重要）
初版报告「535 页完全重复」的结论**不准确**。深挖 `src/content/data/shopify_keyword_use_cases.json` 后发现字段级真相：
- `title` / `scenarioDescription` / `aiPrompt` 均 535 唯一（但后两者只差中间的任务短语）
- `howToSolve` 与 `faqs` 各只有 **167 个唯一值**，平均被 3.2 个关键词复用，最大簇 11 条
- 两种聚簇划分完全一致；164/167 簇在单一类目内
- 同一簇内 `aiPrompt` 的「Use these inputs」与「Return」两段逐字相同
→ 簇内唯一差异字段只有 `title`，**数据层没有可提取的差异化语义素材**。用模板改写做「差异化」= spun content，比原文重复更危险。不要走这条路。

### 已完成的修改
1. `src/lib/seo/metadata.ts`：新增 `truncateDescription()`（CJK 计 2 单位、预算 155、优先句末再词边界），已接入 `buildPageMetadata` 的 description。
2. 4 个 affiliate 页（`/affiliate`、`login`、`register`、`dashboard`）补 `noIndex: true`。
3. 新增 `scripts/seo-description.test.mjs`（6 用例，复用 seo-localization.test.mjs 的 ts.transpileModule + vm 加载模式）。注意：vm 跨 realm 导致 `deepEqual` 失败，需逐字段比较。

### 验证结果
lint 通过（仅 1 条既有 `<img>` 警告）、seo:check / content:validate / build / seo:artifacts 全通过。
本地生产渲染实测：首页 description 204→122、关键词页 358→100、关键词索引→121；affiliate 四页均为 `noindex, follow`；canonical 与 hreflang 未受影响。

### 环境坑（重要）
在本机跑 `npm run build` 会因 `NODE_OPTIONS` 注入 `WorkBuddy .../shim/node-language-shim.cjs` 被 Next.js worker 继承而报 `write EPIPE`。解法：`env -u NODE_OPTIONS npm run build`。与沙箱无关，关沙箱也照样报。

### 新发现（未改，待决策）
`truncateTitleToSERPWidth(title, 480)` 预算写错量级：ASCII 每字符计 0.52 单位，480 预算≈920 字符，**该函数从未触发**。实测关键词页 title 106 字符（Google 约展示 60）。但直接调小常量会从尾部截掉关键词——需同时把格式从 `{描述} — {关键词}` 改成 `{关键词} — {描述}`，预算调至约 32 单位。涉及全站 1691 个 title，未经确认不动。

## 关键词页改造（用户选定：真实撰写，不走 noindex / 不走纯合并）

### 第二次诊断修正（覆盖上文第 26–32 行的结论）
上文说「167 个真实场景」，**这是错的**：167 是**正文簇**（按 `howToSolve` 相同聚合），不是意图数。
逐簇读关键词后发现簇内常混有真正不同的需求——如 20 号簇含 GA4 接入 / Meta 报表 / 多点归因；37 号簇含竞品比价 / 新品监控 / 库存监控；116 号簇含 11 个不同角度的选品查询。
所以「数据里没有差异化素材」也不准确：**关键词集合本身携带 384 个真实意图**，缺的是每页的正文，不是意图。重写成立，但素材必须来自任务结构（触发条件/输入/判定规则/失败模式/产出格式/复核方式），不是字段改写。

### 判定结果
535 词 → **384 个意图页**：独立成页 278 + 合并组规范页 106；纯同义合并掉 151 条 URL（106 个合并组，最大组 6 词）。

- `scripts/build-keyword-content-plan.mjs` —— 校验（关键词精确命中、不可重复分配、默认禁止跨簇）+ 生成 `docs/keyword-content-plan.csv`（535 行，含「你的决定」「备注」待填列，UTF-8 BOM）

## 第二轮试产修订（2026-10-23）

用户评审结论：**第二轮修改稿，暂不发布，不建议据此批量扩写**。主要问题已从「正文重复」转为「规则是否正确、证据是否充分」。

### 模板缺陷（已修复，本轮唯一的源码改动）
`src/app/products/[slug]/playbook/keyword/[keywordSlug]/page.tsx` 的 `splitHowToSteps`：
- 正则 `/(?<=[.!?])\s+(?=[A-Z])/` 对中文无效（无空格、无句后大写），fallback `split(". ")` 同样失效 → **中文页整段被渲染成 1 步**
- 已改为接收 `locale` 参数，`zh-cn` 走 CJK 分支 `/(?<=[。！？])/`，调用处传 `locale`；新增 `import type {Locale}`
- 端到端验收：临时把试产 10 条并入线上数据源 → `next build` → `next start` → 抓取 10 页 × 中英，全部渲染出 6 步；**验收后已还原数据源**（工作区不含试产内容）

### 校验器假阳性修复（scripts/validate-keyword-content.mjs）
评审指出三处失效，全部改掉：
1. 步骤切分改用与模板一致的「按语言分叉」逻辑（原先中英各用一套，与模板都不同）
2. 跨页去重：由「比较英文开头 120 字符」改为全文 5-gram Jaccard，阈值 0.30（中文用 4 字 shingle）
3. 「≥3 处具体数字」：不再只是统计数字词，改为要求数字带单位/口径，并统计跨页复用（>3 页复用即报警）
4. 新增：双语步骤数一致性校验（en 步数必须等于 zh 句数）
5. 新增：提示词必须含「缺项即输出不可判断」兜底指令（中英各自检查）
6. 新增：禁止表述回归清单，命中即失败

### 内容修订（10 页全部重写）
- 转化率：样本量改由四输入推导；删「或 14 天」「取较晚者」「观测差异提前停止」；拆分理论流失金额与可实现增量收入，后者须写明提升幅度与后续成交概率
- 弃购：新增「原因待验证」桶 + 置信度；改三组对照（不发件 / 仅提醒 / 提醒加折扣）以分离邮件增量与折扣增量
- GA4：删除「purchase 未标关键事件」（GA4 中该事件默认为关键事件）；建模不再预设比例，改为说明资格与门槛
- 退款：分开退款 / 退货 / 报废三个事件；各类率写明分子分母；删除错误表述
- 低库存：删除「有在途单即静音」；改为逐日推演断货窗口并与预计到货比对；常态需求与计划促销需求分开预测
- 批量改价：改为取整后重新验证毛利；写明毛利口径；尾数策略降级为待测试项
- 选品：删除「六周有效期」「四至八周衰减」；20% 压力测试标注为示例
- 竞品比价：补齐带时间戳的价格快照序列；删除 14 天硬性判据；抓取频率与 FAQ 统一为「由快照历史校准」
