# 2026-10-23

## GSC「Page with redirect 几百条」排查

实测（生产 https://ciwi.ai，curl 逐跳追踪 + Wayback CDX 比对旧 URL 集合）：

- sitemap 1691 条全部 200；canonical / hreflang / JSON-LD / 站内链接全部使用带尾斜杠形态，自身一致，无「指向 308 的 canonical」问题。
- 根因不是当前站点坏，而是历史 URL 形态遗留：`trailingSlash: true` 于 2026-07-05（commit f8b04ee9）引入，之前站点是「无尾斜杠」形态，Google 索引里留存的都是旧形态。
- 每个现存 URL 的无尾斜杠双胞胎都会 308 → 200（1691 个），一跳，属正常。
- 真缺陷 1：**两跳链**。Next 先做尾斜杠规范化、再匹配 redirects，所以 `/deepl` → 308 `/deepl/` → 308 `/products/translator/`。next.config 里成对写的无斜杠 source（legacyMarketingRedirects）实际是死代码。`legacyRouteMap`(16) + compare 根级(30) 同病。
- 真缺陷 2：**308 终点是 404**。旧 help-center 文档 slug（含 `/help-center/zh-Hans/...` 旧语言前缀，现已无引用）、`/pricing/`、`/vs-g-translate/`、`/vs-transtor/` 等直接 404。因 trailingSlash 打开，每个 404 旧 URL 还额外产生一个 308 双胞胎 → 这正是「Page with redirect」条数被放大到几百的主因。
- 旧 URL 抽样 62 条（CDX）：28 条两跳→200，19 条一跳→200，15 条 308→404。
- 副作用观察：并发 25 抓取时源站大量返回 000 / 103 Early Hints（连接被丢），Googlebot 抓取预算可能受影响，需在 Nginx/Cloudflare 侧核查。

修复方向（未实施，待批准）：middleware 前置解析无斜杠旧 slug 直接 308 到终态；老 URL 建 301 映射，确实下线的返回 410；加 CI 断言 sitemap 内 URL 一跳内 200。
